# 改写示例

以下两例取自真实简历项目。成稿沿用「背景」「指标与效果」「我的职责」的顺序，之后附 STAR 拆解。

## 真实项目改写 · AI 封面图生成工具

- **S · 情境**：多平台内容创作者需要按不同平台的尺寸制作封面。
- **T · 任务**：搭建生成工具，让创作者选平台、提交素材后即可预览和下载。
- **A · 行动**：用 Next.js 实现平台尺寸预设、主体上传与风格参考图输入，将平台场景和风格关键词编入提示词，接入图像生成 API。
- **R · 结果**：工具支持生成并下载适配多个平台尺寸的封面，付费用户可批量生成和导出高清图。

**AI 封面图生成工具**

- **背景与目标**：面向多平台内容创作者，提供从选择平台尺寸、提交素材到生成封面的工作流。
- **我的职责 · 生成链路**：用 Next.js 实现平台尺寸预设、主体上传和风格参考图输入，将平台场景和风格关键词编入提示词，接入图像生成 API，支持多尺寸封面生成、预览与下载。
- **我的职责 · 付费能力**：搭建免费额度与订阅流程，为订阅用户提供批量生成和高清导出。

结果写到已支持的能力。素材未提供点击率变化的测量数据。

## 真实项目改写 · EC-Monica 电商产运 Agent

### 简历成稿

**EC-Monica 电商产运 Agent**

- **背景**：为产品、运营、研发提供电商业务 Agent，支持数据分析与报告生成、业务归因与需求文档解析，缩短业务分析和报告编写所需时间。
- **指标与效果**：上线后月均调用 600+ 次，报告类任务占比约 55%，需求与归因解析类任务占比约 45%。单次分析报告原先人工编写需 1–2 小时，使用 Agent 生成需 5–15 分钟。
- **我的职责**：作为项目负责人，从 0 到 1 完成设计和落地。
  - **Agentic Workflow**：识别用户意图后，根据任务选择调用工具或直接生成。需要查数时，从 Tool Registry 选择工具，循环获取数据并生成子结论，最后汇总为报告。工具层封装超时重试和错误分类，调用失败时降级为直接生成。
  - **Tool Registry**：通过配置动态注册 FunctionSchema，统一管理用户行为、GMV、渠道和商品四类分析工具。新增分析维度时可通过扩展配置接入工具。
  - **Context Engineering**：用 Python 计算同比、环比，再将结果写入模型上下文。把业务范文和运营分析模板作为 Few-shot 样例，引导报告格式。多轮分析中对工具返回的内容做摘要，并用滑动窗口保留近期观察和前轮结论。

### STAR 拆解

- **S**：电商产品、运营与研发有数据分析、归因和报告编写需求。
- **T**：从零设计并落地可处理这些任务的电商产运 Agent。
- **A**：实现任务路由、业务工具注册和上下文管理，让 Agent 能从取数逐步推进到生成报告。
- **R**：用上线调用量、任务分布和单次报告耗时说明实际使用情况。原稿未提供统计周期或样本量。

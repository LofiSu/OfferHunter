# 改写示例

首例改编自真实项目经历，其余为虚构练习。

## 真实项目改写 · AI 封面图生成工具

- **S · 情境**：多平台内容创作者需要按不同平台的尺寸制作封面。
- **T · 任务**：搭建生成工具，让创作者选平台、提交素材后即可预览和下载。
- **A · 行动**：用 Next.js 实现平台尺寸预设、主体上传与风格参考图输入，将平台场景和风格关键词编入提示词，接入图像生成 API。
- **R · 结果**：工具支持生成并下载适配多个平台尺寸的封面，付费用户可批量生成和导出高清图。

**AI 封面图生成工具**

- **背景与目标**：面向多平台内容创作者，提供从选择平台尺寸、提交素材到生成封面的工作流。
- **我的职责 · 生成链路**：用 Next.js 实现平台尺寸预设、主体上传和风格参考图输入，将平台场景和风格关键词编入提示词，接入图像生成 API，支持多尺寸封面生成、预览与下载。
- **我的职责 · 付费能力**：搭建免费额度与订阅流程，为订阅用户提供批量生成和高清导出。

结果写到已支持的能力。素材未提供点击率变化的测量数据。

## 有团队数据，有清晰的个人模块

素材：运营同学生成日报失败后需人工重跑。团队上线异步导出，首周 12 名运营使用。候选人独立实现导出任务的重试和幂等；全队首周统计显示，人工重跑从上线前一周的 20 次降到 6 次。没有该模块的独立归因数据。

STAR 素材拆解

- S：日报生成失败后，运营需要人工重跑。
- T：团队交付异步导出。候选人负责重试与幂等。
- A：实现自动重试，并按任务 ID 去重。
- R：团队上线后首周有 12 人使用，人工重跑较上线前一周由 20 次降到 6 次。

**日报异步导出 · 后端开发**

- **背景与效果**：运营日报生成失败后需要人工重跑。团队上线异步导出，首周 12 名运营使用，人工重跑从上线前一周的 20 次降至 6 次。
- **任务重试与幂等**：独立实现导出任务自动重试，按任务 ID 去重，避免重复执行时生成多份导出文件。

完整项目版可再补失败分类或重试上限，但只有素材能支撑时才写。投递稿只需保留能说明设计取舍的细节。

## 没有指标，需要一条就能投递

素材：用户维护商品编辑页，有时表单切页后会丢失。用户给编辑页加了本地草稿，按商品 ID 分存，提交成功后清理。已上线，目前没有埋点。

- **编辑草稿恢复**：为商品编辑页实现按商品 ID 隔离的本地草稿，重新进入页面时恢复未提交内容，保存成功后清理对应草稿。

如果岗位关注前端状态管理，面试材料可以进一步追问跨标签页冲突和草稿过期策略。当前素材只支持写已实现的恢复行为。

## 同一素材按岗位取舍

素材：候选人为知识库独立实现流式渲染和中断恢复，并参与编写模型评测脚本，评测指标由另一位同事制定。

- **前端岗位**：优先写流式渲染与中断恢复。素材确认了分段渲染、状态回放或错误处理时，再补其中最能体现工程判断的机制。
- **AI 应用岗位**：可以补评测脚本的具体分工，如实现批量执行和结果汇总。指标设计仍归对应同事。其余项目更能说明评测能力时，把它们放在前面。

## 同一个 AI 项目，分别投评测岗和产品岗

虚构素材：客服团队试点知识库助手。候选人从历史工单选了 60 条问题，按引用错误、回答不完整和应拒答分类，复测两个版本。候选人还访谈 5 名客服，据此定义「回复前确认引用」的验收条件。研发同事实现功能，团队已完成内部试点，尚无线上指标。

- **AI 评测岗 · 离线回归**：从历史工单整理 60 道离线评测题，按引用错误、回答不完整和应拒答归类，完成两个版本的回归复测。
- **AI 产品岗 · 工作流验证**：访谈 5 名客服，将「回复前确认引用」写入知识库助手验收标准，对应工作流已进入团队内部试点。
- 如果 JD 明确要求生产监控或从试点扩到多团队，分别追问是否有对应的真实经历。内部试点范围可以写进简历，待确认资料放在成稿之后。

## 真实项目改写 · EC-Monica 电商产运 Agent

### STAR 素材拆解

- **S · 情境**：电商产品、运营和研发需要读懂 A/B 实验与业务看板、生成报告、定位业务波动原因并解析需求文档。
- **T · 任务**：作为项目负责人，从零设计和落地电商产运 Agent。
- **A · 行动**：按意图在工具执行和直接生成间路由。通过配置动态注册工具 schema，集中管理用户行为、GMV、渠道和商品分析工具。用 Python 计算同比和环比，将结果写入上下文。模型逐轮生成子结论，最后汇总成报告。工具层处理超时重试、错误分类和降级。用业务范文和运营模板引导输出，同时对工具观察做摘要与滑动窗口截断。
- **R · 结果**：简历记录上线后月均调用 600+ 次，其中约 55% 为报告任务、约 45% 为需求与归因解析。单次分析报告从人工编写 1–2 小时，变为使用 Agent 生成 5–15 分钟。原稿未交代统计周期和样本量，后续可补充核验。

### 可投递写法

**EC-Monica 电商产运 Agent**

- **业务背景**：面向电商产品、运营和研发，为 A/B 实验和业务看板提供数据分析与报告生成，并支持业务归因和需求文档解析。
- **指标与效果**：上线后月均调用 600+ 次，约 55% 为报告任务，约 45% 为需求与归因解析。单次分析报告人工编写需 1–2 小时，使用 Agent 生成需 5–15 分钟。
- **我的职责**：作为项目负责人，从零设计并落地以下链路。
  - **Agentic Workflow**：识别意图后路由到工具执行或直接生成，循环执行工具、生成子结论，最终汇总报告。工具层封装超时重试与错误分类，失败时降级为直接生成。
  - **Tool Registry**：通过配置动态注册 FunctionSchema，统一管理用户行为、GMV、渠道和商品四类分析工具。新增分析维度时可通过扩展配置加入工具。
  - **Context Engineering**：用 Python 预计算同比与环比后注入上下文，通过业务范文和运营分析模板引导输出，并用摘要与滑动窗口保留多轮分析中的关键结论。

投 AI 应用工程时优先保留三个技术小标题。投 AI 产品时先写服务对象、任务分布与报告耗时，把技术实现压缩成一条。

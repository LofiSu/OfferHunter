# Apply to a BOSS Zhipin role

[简体中文](boss-application.md)

## Tailor the resume

1. Read the posting, screenshot, or job description. Identify the job title, the main work, and what the hire is expected to deliver. If the link shows only the title or cannot be opened, ask for the job description or a screenshot. Use any confirmed details to make partial progress.
2. Choose one to three relevant projects. Pick examples that show what the candidate personally owned, how they did the work, and what happened. Use actual tools, responsibilities, and results. For transferable experience, keep the original context and explain what carries over.
3. Move the best evidence up and shorten less relevant entries. Write every project under **Background**, **My Responsibilities**, **Action**, and **Result**. If the user asks to edit one project, give them the replacement text. Mention any important gap separately.

For a key project, show where the work happened. List the employer or team, role, and dates above the entry when available. Describe the candidate's scope and then walk through two or three relevant implementation steps. For an operations agent, for example, describe how it decided when to query data, chose a tool, handled failures, and assembled a report. Use verified outcomes and specify the baseline and scope when available.

## Draft a first message

Name the role, then give one related project. Say where you did the work, what you owned, and one or two technical details that match the job. Add a verified result or a public work sample if it strengthens the message. Close with a simple invitation to talk. If the user gives a length limit, keep the project context, ownership, and most relevant detail.

> Hi, I'm interested in the AI Application Engineer role. During my e-commerce internship, I owned the design and launch of an analytics agent. I built the tool-routing flow to query data, calculate year-over-year and period-over-period changes, and turn the findings into reports. I also handled tool retries and fallback behavior. I'd be happy to discuss how this experience fits your team.

Give the user copy-ready text. Ask for a relevant project if there is too little evidence to write a credible message.

## 按工作步骤找 STAR 素材


### Agent 与 RAG 应用

1. **确定任务与边界（S、T）**。谁在执行什么任务？原流程卡在查资料、调用系统还是汇总结果？你负责知识库、工具编排、用户界面，还是整条流程？
2. **准备资料并验证检索（A）**。如果做过知识库，讲清文档从哪来、按什么边界切分和更新。说明如何用真实问题检查召回。加过重排时，举一个原始检索排序不对、后来能找到正确依据的例子。
3. **接入工具并处理失败（A）**。如果做过 Agent，写清怎么判断要走哪条路径、工具参数怎么校验、执行失败时怎么重试或转人工。带权限的业务操作可以说明在哪里要求用户确认。
4. **核对结果（R）**。用任务完成率、引用准确性、转人工率或耗时说明效果。注明数据来自离线题集、内部试点还是线上。做的是检索模块时，优先给检索本身的评测，再注明已观察到的端到端变化。

### 模型训练与应用研究

1. **定研究问题（S、T）**。原模型在哪类样本上有问题？目标是提升领域任务、指令遵循还是其他能力？你负责数据、训练策略、实验设计中的哪一部分？
2. **准备实验（A）**。记录基座版本、数据来源、清洗规则和训练／验证／测试划分。说明基线是什么，以及哪些变量保持一致。
3. **训练和排查（A）**。写清实际改过的数据配比、训练策略或模型模块。选一个关键决定，说明依据是什么，使用哪些日志或样本发现问题。
4. **复测（R）**。在同一任务和测试集上比较基线与改动版本。记录指标、失败样本和适用范围。只做了复现时，可写复现结果和发现的差异。

### 数据、标注与模型评测

1. **确定覆盖范围（S、T）**。评测面向哪些用户、场景和失败类型？你负责设计题集、组织标注、编写执行工具，还是分析结果？
2. **准备样本与规则（A）**。记录样本来源和分布，挑一个边界案例说明如何制定正确答案、可接受回答或拒答标准。数据岗位也可写清去重、抽检和版本维护。
3. **执行与复核（A）**。说明怎么分配样本、处理评审分歧、复核疑难样本。用了模型裁判时，交代如何与人工复核结果对照。
4. **交付与复测（R）**。写题集规模、抽检覆盖范围、跨版本变化，或某类失败被修复后再次验证的结果。把样本数、评测版本和结果归属写清楚。

### 推理、部署与 MLOps

1. **先定服务要求（S、T）**。原服务卡在延迟、吞吐、显存还是稳定性？写明你负责部署、压测、监控或发布的哪一部分。
2. **建立可比较的基线（A）**。记录硬件、模型版本、输入与输出长度和并发水平。说明在什么负载下出现瓶颈。
3. **改动与发布（A）**。具体写调了批处理、缓存或量化中的哪一项，为什么这样选。负责发布时，再说明灰度、告警或回滚如何验证。
4. **报告系统表现（R）**。用同负载下的首字延迟、P95、吞吐、显存占用或单位成本比较前后变化。若优化牺牲了质量或容量，也写明边界。

### AI 产品、设计与解决方案

1. **收窄使用场景（S、T）**。用户原来怎么完成任务？哪一步最费时，哪一步需要人做决定？说明你负责需求、交互、客户验证还是交付。
2. **定义验收标准（A）**。把目标改写成可检查的场景，例如输出是否附引用、用户能否修正错误、无法回答时怎么提示。挑一个实际取舍，说明为什么先做某个功能。
3. **做原型与试点（A）**。说明谁参与试用、试的是哪段流程、反馈怎么进入下一轮。解决方案岗位还可写清数据接入、权限和客户验收各由谁负责。
4. **凭证据写结果（R）**。可写已验收的场景、试点范围、用户完成任务的表现或业务方采纳情况。原型和正式上线分别写明。

### 多模态、语音视觉与机器人

1. **写清输入和使用条件（S、T）**。任务用图像、视频、音频或传感器中的哪些数据？实际场景有什么光线、噪声、设备或响应时间限制？
2. **指出自己负责的一段（A）**。可以是数据对齐、预处理、特征融合、模型训练或设备集成。举一个影响效果的边界问题，写清你如何定位和处理。
3. **区分验证环境（R）**。注明离线、仿真或实机，记下对应设备、数据范围与典型失败。能复测时，在同一组场景比较改动前后的结果。

### 安全、治理与合规

1. **说明风险边界（S、T）**。哪些用户或系统会受影响？你负责制定规则、执行评估、设计控制，还是跟进整改？
2. **写清评估和决策（A）**。说明风险如何分级、抽样怎样覆盖边界场景、谁复核例外。写自己产出的检查表、审查记录或整改方案。
3. **展示可验证的交付（R）**。注明审查覆盖范围、流程实际在哪些团队采用，或哪些问题已经复审关闭。团队结果和个人贡献分别注明。

### 技术管理、研究管理与开发者关系

1. **说清团队目标与约束（S、T）**。团队要交付什么，卡在资源、协作还是采用？说明你能决定什么，以及哪些环节依赖他人。
2. **描述具体推动动作（A）**。写一个改变路线、分工、验证计划或外部接入方式的决定，说明如何和相关人员对齐。开发者关系岗位可以写自己维护的示例、文档和反馈渠道。
3. **用交付、采用或进展佐证（R）**。例如某个里程碑按约定验收、下游团队采用工具、开发者问题得到复现和解决。注明团队整体结果与个人负责范围。
